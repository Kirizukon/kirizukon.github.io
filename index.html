  7. ( 07 ) Sécurisation d’infrastructure / CHU Santé+ opnsense / windows server / gpo / pki / attack navigator Architecture

    Sécurisation de bout en bout du système d’information d’un centre hospitalier, des exigences jusqu’à la maquette qui les démontre. Trois volets : un dossier d’architecture technique (classification des données, zones de confiance et matrice de flux en refus par défaut, exigences réglementaires, authentification et PKI, plan de durcissement) ; une analyse de risque adossée aux 42 mesures du guide d’hygiène ANSSI, avec la posture actuelle et la posture cible cartographiées dans MITRE ATT&CK Navigator ; une preuve de concept sur maquette de cinq machines.

    Sur la maquette : segmentation et règles de filtrage sur OPNsense, domaine Active Directory en modèle de niveaux (tiering), 18 GPO liées par unité d’organisation avec la baseline en dernier rang, Protected Users, stratégies de mot de passe granulaires, suppression de WDigest, protection LSA, abandon de NTLMv1, pare-feu du poste par GPO, procédure de bris de glace tracée et alertée, PKI racine et émettrice sous OpenSSL, durcissement Linux du serveur applicatif. Les durcissements sont portés par des scripts PowerShell idempotents, dont un contrôle d’écart rejouable, et chaque mesure est prouvée (HardeningKitty, gpresult, auditpol).

    Stack
    OPNsense / Windows Server / Active Directory / GPO / PowerShell / PKI OpenSSL / Debian / Rocky / PostgreSQL / MITRE ATT&CK Navigator
    Référentiels
    Guide d’hygiène ANSSI (42 mesures) / CIS Benchmarks / MITRE ATT&CK

  8. ( 08 ) Laboratoire TLS / 11 challenges tls / scapy / docker / ansible / packer Offensif

    Laboratoire d’attaque de la sécurité du transport HTTPS, conçu et construit de bout en bout : onze challenges de type capture-the-flag, deux d’échauffement (OpenSSL, Scapy), un d’interception en clair qui installe la posture d’attaquant réseau, puis huit qui mettent en défaut, de façon contrôlée, une propriété distincte de TLS : confidentialité, intégrité, authentification du pair.

    Le modèle de menace est l’attaquant réseau actif (Dolev-Yao) placé en homme du milieu par empoisonnement ARP. Chaque pile cible est volontairement vulnérable (échange RSA sans confidentialité persistante, DHE export 512 bits, SSL 3.0, TLS 1.0 en CBC, OpenSSL 1.0.1f), et chaque attaque est refermée par sa contre-mesure normative : validation RFC 5280, ECDHE, groupes DH d’au moins 2048 bits, HSTS, TLS_FALLBACK_SCSV, découpage 1/n-1. Principe de conception : le portail applicatif n’est jamais cassé au niveau applicatif, la faille est toujours dans la couche de transport posée devant lui. J’ai écrit l’oracle de padding POODLE en Python, et le laboratoire se déploie seul (Docker Compose, Ansible, Packer, Makefile) avec son guide étudiant.

    Usage pédagogique. Le laboratoire embarque volontairement des piles TLS vulnérables. Il doit tourner exclusivement sur un réseau isolé, jamais routable vers un réseau de production ni vers Internet.

    Rapport PDF GitHub
